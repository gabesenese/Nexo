# Nexo: working notes for Claude

Read this first. It is the handoff from the long session that produced the strategy, research and
fixes described below. The detail lives in the files it points to; this file says where things stand
and how to behave.

## What Nexo is

AI customer-support agent for small SaaS teams (2-20 people on support). It answers only from the
customer's own help center and PDFs, cites what it used, and hands everything else to a person with the
whole thread. Fastify + TypeScript API, React admin console, embeddable widget, static landing page,
Postgres with pgvector. Cloud AI is Claude (answers) plus OpenAI (search embeddings only).

```
packages/server   API, ingestion, retrieval, orchestrator, billing, scripts
packages/admin    console (React)
packages/widget   embeddable chat widget
packages/landing  public marketing page
eval/head-to-head test kit: Nexo vs Fin, Chatbase, Tidio on one real help center
outreach          buyer research: call script, company list, call log (real data is git-ignored)
```

## The rules

1. **Scope freeze** (`structured-plan.md`): no new features, design passes, integrations or strategy
   documents until 5 buyers commit to a paid pilot, or 20 buyer conversations are done and a decision
   is logged. Allowed: fixing untrue claims, measuring cost, bugs and security, work a design partner
   asks for in writing, and what the buyer research needs. If asked to build something frozen, say so
   and ask whether they want an exception.
2. **No claim without evidence.** Never quote a resolution rate unless measured on a real workspace
   with the definition in `RESOLUTION.md`, with sample size and period. The 66% figure was invented
   demo data and is withdrawn. Do not claim Canadian data residency: answers are generated by
   Anthropic and OpenAI, and nothing is deployed. Landing-page copy changes need the same scrutiny.
3. **Silence is not a resolution.** A handoff is never credited to Nexo. See `RESOLUTION.md`; the
   Impact page, its tests and the website FAQ must say the same thing.
4. **Conversations are never refused**, but past a plan's allowance times `FAIR_USE_MULTIPLIER`
   (default 2) new ones go to the workspace's own team, not the AI. The landing page says "twice"; if
   the multiplier changes, change the page.
5. **This repo is public.** Never commit `.env`, API keys, or real prospect data. Everything in
   `outreach/` except the templates and `kw-seed-companies.csv` is git-ignored on purpose.
6. **Do not cite numbers from memory.** Competitor prices, Claude model prices and legal rules
   change. Verify, or say they are unverified. Most research sources were vendor blogs.

## Running things

```bash
npm install
docker compose up -d                              # Postgres + pgvector
cp .env.example packages/server/.env              # must be packages/server, not the root
npm run db:migrate --workspace=@nexo/server
npm run dev                                       # server :4000, console :5173
```

Tests need a database and these variables (CI sets the same):

```bash
export DATABASE_URL='postgresql://nexo:nexo@localhost:5432/nexo_test?schema=public'
export JWT_SECRET=ci_jwt_secret_ci_jwt_secret_ci_jwt_secret
export INTEGRATION=1
npx prisma migrate deploy --schema packages/server/prisma/schema.prisma   # once, against the test DB
npm test --workspace=@nexo/server                                         # 234 pass, 1 skipped
npm run typecheck                                                         # server, landing, widget, admin
```

Gotchas learned the hard way:
- `npm install` rewrites `package-lock.json`. Do not commit that change; `git checkout package-lock.json`.
- Production builds of the landing page and console refuse to run without settings (`VITE_CONTACT_EMAIL`
  or a lead endpoint for landing, `VITE_API_URL` for the console). That guard is intentional. Pass a
  throwaway value to check a build.
- Write migrations with `prisma migrate diff --from-schema-datamodel <old> --to-schema-datamodel <new> --script`
  so they match the schema exactly, then apply and run the suite.
- `pkill -f` matches your own shell command line. Kill by process ID.
- Several newer Claude models (Sonnet 5.5, Opus 5.5) reject this code's forced tool call and its
  disabled-thinking setting. Changing `ANTHROPIC_MODEL` is a code change plus a quality test, not a
  config flip. Current default is `claude-sonnet-5`.

## What to do next, in order

1. **Run the head-to-head** (`eval/head-to-head/README.md` has the full setup). It needs the founder's
   Anthropic and OpenAI keys and their own Fin, Chatbase and Tidio trials. Run `npm run eval:coverage
   --workspace=@nexo/server` first: the crawler stops at 100 pages and the Plausible docs have about 135.
2. **Read the real cost**: `npm run cost:report --workspace=@nexo/server`. Cost per conversation is still
   unmeasured; any figure so far was an assumption. Decide `FAIR_USE_MULTIPLIER` from it.
3. **Buyer conversations** (`outreach/README.md`, `MARKET-VALIDATION.md`): 30 calls or two weeks, then
   run `node outreach/summary.mjs` and decide what to change. Check each prospect's support chat and
   reviews first (`outreach/bot-checks.md`). Rank prospects by evidence that support is struggling,
   not by whether they have a bot.
4. **Name, trademark, domain.** `structured-plan.md` says this blocks launch. Not started.
5. **Test the verification idea** with buyers: companies already running Fin or Zendesk AI have the
   "how do I know it resolved?" problem and a budget (`REALITY-CHECK.md`, pivots).
6. **When a prospect says yes:** Deployment Phase 1 (`DEPLOYMENT.md`), about C$5 a month. Put a precise
   data-handling statement back on the website only once the platform runs somewhere a reader can check.
